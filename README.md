# Legends Viewer（纯浏览器版）

**Byayoi同人社区** 制作。项目原创代码与移植的 DFCN 内容采用与 DFCN 相同的 **CC BY-NC-SA 4.0（署名—非商业性使用—相同方式共享）**；第三方资源保留各自许可与署名，见 [LICENSE](LICENSE) 和 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

使用 HTML、JavaScript、CSS 在浏览器本地读取 Dwarf Fortress Legends 导出文件。无需 Node.js、后端、构建步骤或网络连接，直接打开 [index.html](index.html)。

页面结构、导航、默认深色主题、列表列定义和详情卡片顺序按 [Kromtec/LegendsViewer-Next](https://github.com/Kromtec/LegendsViewer-Next/) 源码移植；保留原名称 Legends Viewer 与标志。正文和导航为 16px，辅助文字不低于 14px。列表、详情、世界纪录、家族树和图表沿用原版的信息结构；内容来自导入文件及原版可推导的数据。

## 使用

1. 在游戏 Legends 模式导出 XML；可用 DFHack 获取 `legends_plus.xml` 补充数据。
2. 打开页面，在“探索新世界”卡片点击“选择”，选中同次导出的主 XML、可选的 Plus XML 和世界地图图片。
3. 载入后使用原版分组导航浏览世界、地图、人物、派系、地点、神器、时代与纪事。列表支持搜索、筛选、列排序和分页；详情在主页面打开。

陆块、河流、山峰来自 `legends_plus.xml`，游戏自带的主 `legends.xml` 不含这三组记录。使用 DFHack 时，在 Legends 模式运行 `exportlegends` 可生成补充文件；也可启用 “Also export extended legends data” 后点击游戏的 Export XML，一并导出两份 XML（[官方说明](https://docs.dfhack.org/en/stable/docs/tools/exportlegends.html)）。在本页面的文件选择器中同时选中同一世界、同次导出的主文件和 Plus 文件再载入；单独选择 Plus 不会为已有世界追加数据。陆块位置按上游读取 `coord_1`、`coord_2` 两个原始坐标，不根据端点虚构面积。

已载入的世界可单独追加或替换地图底图：回到“探索世界”，点击“选择”，仅选中该世界的 PNG/BMP 等地图图片。会保留当前世界、原始 XML 来源与索引，直接更新并保存底图；不必重新选择大 XML。无效图片不会覆盖现有底图。

世界显示后，原文件会以每块最多 8 MiB 的独立 Blob 在后台保存到当前浏览器的 IndexedDB；全部写入后再发布原文件目录。成功保存的世界显示为首页卡片，收藏显示在左侧导航。后台保存期间可继续浏览和使用导入控件。若保存失败，本次已载入的世界仍可读取，但刷新或关闭页面后不能恢复这个尚未保存的新世界，需要重新选择原文件。清除浏览器数据后也需重新导入。

XML 总大小超过 32 MiB 时，会自动在浏览器后台线程中建立文件位置索引：准备阶段直接读取选中的 File，不再等待整个文件先写入数据库。记录位置和查询字段分块保存，列表、详情按需读取原 XML 片段；世界可见后再后台保存原文件。JavaScript 不会构造整份 XML 字符串或逐条复制数百万条完整记录。首次需要扫描文件，同版本索引下从首页打开成功保存的世界无需重新扫描。点击“取消”会立即返回，临时索引在后台清理。

新导入的文件索引使用独立的 `legends-file-index-v3` 数据库（schema 1），与旧版 `legends-file-index` 分开，避免旧页面连接阻塞新导入；已有世界按保存的来源数据库读取。

首次打开较早版本生成的世界索引时，会进行一次索引字段与派生统计升级，并保存更新后的世界元数据。升级成功后，再次打开或刷新会复用同版本索引和原文件来源，无需重复扫描。

列表直接读取当前页所需的查询字段，详情按对象的关联索引读取事件；家族树只读取原版实际绘制的亲属。独立的关联与角色缓存会在首次使用时从已有索引建立，按原版规则补齐参战人物、巨兽、派系及时代纪事；不替换世界索引或派生统计。后续页面和刷新复用这些缓存。事件与纪事各自保留页码、排序和每页条数，图表与总数使用完整数据。

艺术形式在导出中没有单独名称时，按原版从描述的第一句提取名称；描述保留全文、条目与滚动布局。旧索引未保存的地点矩形，仅在首次查看河流时按需从地点原文补齐，不重新导入世界。

## 本地缓存读取与恢复

大索引块、统计和世界元数据在写入前编码为带有界 Blob 片段的轻量描述值，保留 TypedArray 类型及共享缓冲区；旧格式仍可读取。临时的 IndexedDB 大值读取错误最多重试三次，同一原文件或索引块的并发读取只发起一个请求。这里处理的是大结构化值的读取，并不把原 XML 的 File 内容误当成数 GB 的 JavaScript 对象。

索引块持续不可读或缺失时，从同一原 XML 重放索引批次，找到目标块即停止；验证记录数、ID 边界、主记录标记和顺序后，只改写该块，保留原索引标识、其他统计及排名。校验失败不会覆盖旧数据。若连原文件缓存也无法读取，原有导入对话框会提示重新关联原 XML；按文件名和大小验证，并保留原文件槽位及已有索引，无需重新导入整个世界。

重新选择同次导出的全部 XML 后，页面立即恢复浏览，并在后台修复原文件缓存。主 XML 和 Plus XML 的新分块全部写入成功后，才在同一事务中替换目录；失败或取消保留旧缓存及本次已选原文件的浏览能力。看到“原文件缓存已修复，可直接刷新恢复。”后即可刷新，下次无需重新选择。损坏的旧缓存无法提供原文时，浏览器仍需要用户选择一次原 XML。新缓存读取只加载所需分块，最多并行读取 4 块，分块缓存上限 64 MiB；兼容原有 File 缓存和旧来源数据库。

Chromium 对超过阈值的结构化值使用内部大值包装；这条读取错误并不单独证明 XML File 太大。实现依据：[Chromium 大值包装](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/modules/indexeddb/idb_value_wrapping.cc)、[读取错误分类](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/modules/indexeddb/idb_request_loader.cc)。

## 翻译

继续使用本机 `dfcn` 的译名词表、姓名构词、中心词、地点及政府后缀、英式音译和 G2P 模型。算法与导出元数据边界见 [TRANSLATION.md](TRANSLATION.md)。原名参与列表搜索。技能等级、事件叙述和页面术语的来源、覆盖及边界见 [TRANSLATION_COVERAGE.md](TRANSLATION_COVERAGE.md)。

神器有专名时使用上述译名算法；只有物品描述时，使用 DFCN 的物品、材质及品质符号入口。例如 `primordial wood crossbow` 为“原初木十字弩”，`primordial wood` 单独作为材质时为“原初木头”。原始 `name`、`item.name_string` 和符号保留，已有世界可直接使用新的显示翻译；英文和中文均可检索。来源中的未知物品描述保留原文。

## 静态资源

- `js/data.js`：分块读取、校验和合并 XML；不上传文件。
- `js/import-client.js`：本地 Blob Worker、导入取消及分批通信，直接打开 HTML 即可使用。
- `js/local-store.js`：书签、本地世界管理及已有数据库格式的兼容读取。
- `js/file-indexer.js`：按原始字节定位记录，只提取查询字段与纪事关系，支持 CP437、UTF-8 和 UTF-16。
- `js/fast-store.js`：原文件分块缓存与位置索引的存储、原文件恢复、按页查询、记录片段复读；大文件默认使用此路径。
- `js/app.js`、`js/details.js`：本地数据适配与原版列表、详情页面渲染。
- `js/upstream-ui.js`：从上游页面提取的导航、标题、表格列和分类定义。
- `js/storage-values.js`：大值的有界 Blob 编码、类型恢复与有限读取重试。
- `js/map.js`：导入地图图片与地图视图的浏览器适配。
- `js/records.js`：按上游纪录页面显示分类和纪录卡。
- `js/family.js`、`js/filters.js`：原版家族树图谱和分类筛选控件。
- `js/translate.js`、`translation-data.js`、`translation-phonetics.js`：DFCN 名称翻译。
- `js/translation-ui.js`、`translation-ui-data.js`：DFCN 历史文本、原版技能表与界面中文句式。
- `js/item-translate.js`、`translation-item-data.js`：DFCN 物品名称、材质的名词与修饰形态、品质符号及对应规则；由 `tools/import-dfcn-items.py` 只读导出来源数据。
- `assets/`：随页面分发的原版标志、Roboto、MDI、Leaflet 1.9.4、Chart.js 4.4.8，以及原版 Cytoscape / Dagre 图谱依赖；无 CDN 请求。
- `tools/import-dfcn.py`：可选的数据维护脚本，网页运行不需要 Python。

文件解析、查询和存储在浏览器中完成。压缩包需先解压；大文件需要足够的浏览器本地存储空间。XML 未提供的游戏内存字段无法从页面恢复，相关卡片只显示有依据的数据。

## 导入线程与缓存管理

导入窗口提供“双线程”和“单线程（兼容模式）”。XML 总大小超过 32 MiB 时，默认由一个后台线程解析、另一个后台线程编码并写入索引，最多排队两批记录；小文件仍使用单个解析线程。不支持嵌套 Worker 时自动退回单线程。此处是两阶段流水线，统计仍按依赖顺序执行，不是任意数量线程的解析任务池。

磁盘索引的导入结果与统计结果通过 IndexedDB 交接，线程消息只发送结果标识。缓存读取不再把数据库持有的 Blob 句柄拼成新 Blob；原文件按最多 8 MiB 的独立字节块保存和恢复，读取缓存上限仍为 64 MiB。这些调整用于降低大数据交接及 Blob 句柄生命周期的风险，不能仅凭错误码断言已修复所有 `RESULT_CODE_KILLED_BAD_MESSAGE` 情况。

在“探索世界”首页，世界卡片的“更多”菜单支持删除导入地图和删除世界缓存，包括当前世界。删除地图保留 XML 与索引，仍可显示根据地理数据生成的底图。首页下方还可清理失败导入残留，或清空全部世界缓存；操作前有确认，不删除磁盘上的原始 XML 和图片。清理前请关闭其他旧版本页面；新版页面使用浏览器锁协调导入与清理。

若导入中断，可重新打开页面，在导入窗口导出上次导入诊断。诊断记录文件名、大小、浏览器版本和最后进度，不记录 XML 正文。Windows 用户也可双击根目录的 `一键启动.bat` 打开页面，无需安装额外运行环境。

新增本地回归覆盖线程模式对照、取消、写入失败、线程降级、超过阈值的自动磁盘索引、缓存恢复、残留清理、删除地图及当前世界。测试使用 Node VM 模拟 Worker、fake-indexeddb 与 jsdom，不替代真实 Chromium 的多进程、Blob IPC 或性能验证。可选开发依赖仅用于运行测试，网页运行不需要 Node.js：

```sh
npm --prefix tests ci
npm --prefix tests test
```

## 开发验证

无需 Node.js。安装了 SpiderMonkey 的环境可运行 `js140 tests/parser-shell.js` 验证解析与合并；运行 `js140 tests/parser-stress.js 3994` 验证约 3.9GiB 的流式读取。压力夹具按块生成，不会在测试开始前构造一个巨大的字符串。

实际世界文件 **4,164,648,495 字节**在本机普通 `file://` Chromium 中，采用新分块缓存的一轮 **86.335 秒**完成索引与原版派生统计；保存后刷新，事件末页、**98,393** 人物列表和人物 96 详情全部通过，浏览器无错误。该世界 XML 原有 **1,376,956** 条事件，另按上游战役逻辑派生 **3,613,890** 条 `battle fought`，页面合计 **4,990,846** 条。耗时取决于文件内容、浏览器和设备。此前早取消后立即重试与取消数据隔离也已验证。

同一真实世界的旧索引升级验证中，从索引字段版本 2 升至 3、派生统计版本升至 4，连同元数据保存和人物详情载入用时 **94.662 秒**；随后刷新 **5.965 秒**恢复，未创建索引 Worker，也未再次扫描索引字段。条件式事件关系同步验证通过，包括人物 426 的相关事件列表包含原始事件 3609。

文明缺少种族时，依据保留的人物在任职位关系补齐，并沿用原版的按种族配色公式。已有版本 5 缓存首次补齐只遍历人物索引，以 `civilizationRacesVersion: 1` 标记；不重读原 XML、不替换索引或重算其他统计，后续打开直接复用。成员关系、前任职位与恶魔种族不用于猜测。旧缓存只保留最终文明集合，未保留原版处理职位关系时较早的 `IsCiv` 状态，因此此处补齐的执行时点与上游不同；不宣称逐步复现这一处理顺序，也不保证真实世界的每个未知种族都能恢复。

当前派生统计为版本 5，区分主文明与野生动物群体，并保留原版庆典、盗窃等事件确立的无名文明。字段索引仍为版本 3；从统计版本 4 更新只重算已有索引，复用原文件与索引位置。概览文明卡片按原组件显示缩略图、统治者、据点及人口徽章；只有明确关联的人口数据才用于人口统计。

“复制最多的手稿与书籍”按明确的 `artifact copied` 事件数与其他作品的 `WRITTEN_CONTENT` 引用数之和排名，并显示两项明细。同一引用作品对同一目标只计一次，排除自引；持有、存放、赠予和创作等事件不计入。只有复制或被引用次数大于零的作品进入排行，数值表示导出记录中可确认的次数。已保存的版本 5 世界首次打开时，从现有索引更新这一排行并保存 `copiedWorksVersion: 1`；原文件、索引和其他统计继续复用，后续刷新直接读取修正后的缓存。

本轮对同一实际世界分次验证了 34 类、86 个列表页和 44 次详情完整内容，列表显示中位 102 ms、最大 196 ms；人物 0/6 完整详情约 868/1201 ms，建筑和时代详情约 147/181 ms。全部保留原始字段、关系卡片、完整统计及分页；12 个人物与 3 个时代的全部纪事 ID 另与原 XML 独立解析结果逐项一致。浏览器无错误，原 920 个索引块、索引标识及主统计哈希未变。已有世界首次补建两份辅助缓存仍需约 **11.28 秒**；正常刷新完整人物列表约 **1.40 秒**，该次原 XML 读取为零。首次补齐时间不能当作普通页面切换时间，以上仅代表本机测试。

```sh
python tests/browser-translation.py
python tests/browser-pages.py
python tests/browser-nonblocking-import.py
```

首次导入故障回归使用约 160 MB 的临时 File，分别模拟后台保存永久等待和立即失败：两种情况都在绘制帧回调不执行时启动保存，并可浏览世界、末页和人物详情，导入控件恢复可用；随后选择其他文件仍从原世界的正确来源读取。同时保持旧版数据库连接不关闭，验证新索引数据库不受阻。该填充夹具用于故障路径验证，不能替代上述真实世界测试。

完整导入、取消、存储和刷新验证可运行 `python tests/browser-import.py --large`；`--expected-events` 比较 XML 原始事件数，分页使用含派生事件的页面总数。测试只使用 Python 标准库和 ChromeDriver 的浏览器控制端口，不启动应用 HTTP 服务。详情见 [tests/README.md](tests/README.md)。

原版使用服务端文件选择，本版本对应位置改用浏览器文件选择，这是本地文件权限所必需的调整。

本次真实 XML 的 `entity_populations` 只有 ID，地表区域没有 `coords`，也没有配套地图 BMP。人口和面积环图因缺少可计算的数据，按原版 `World.vue` 的条件隐藏；图表数据齐全的导出仍显示相应图表。地图还可使用区域坐标生成底图，因此缺少 BMP 本身不等于必须隐藏地图。
